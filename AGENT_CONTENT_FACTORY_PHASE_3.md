Продовжуємо «Agent Content Factory». Зараз зв'яжемо агентів у рой: одна ціль власника = один «прогін рою», де Стратег планує та роздає завдання, виконавці їх роблять, Критик перевіряє, а Стратег пише підсумкове зведення (summary).

Зроби:

1. База даних. Додай таблиці або проаналізуй, чи вони є (через безпечну міграцію db/migrate.sql, щоб не втрачати дані, та команду npm run db:migrate):
   - runs — прогони рою (ціль, статус, зведення).
   - tasks — дошка завдань (агент, опис, статус, результат, вердикт Критика, залежності між завданнями, номер кола доопрацювання).
   - events — стрічка сповіщень для власника (лічильник у дашборді).
   - activity_log — журнал: хто що зробив по кожному прогону.

2. Бекенд — система прогону:
   - src/agents/orchestrator.ts — рушій прогону: планування (Стратег розбиває ціль на завдання) → виконання → перевірка Критиком (до 2 кіл автодоопрацювання) → зведення власнику.
   - src/agents/queue.ts — фонова черга: виконує завдання по одному, не блокуючи дашборд. Якщо бекенд перезапустити посеред прогону — незавершені завдання підхоплюються при старті.
   - src/agents/tools.ts — «руки» агентів у прогоні, описані через zod та вбудований MCP-сервер Claude Agent SDK, прив'язані до конкретного прогону/завдання.
   - src/journal.ts — журнал роботи рою та стрічка сповіщень.
   - Маршрути src/routes/runs.ts та src/routes/events.ts: запустити прогін, дізнатися статус, список завдань, схвалити/відправити на доопрацювання результат.
   За замовчуванням виконавцями стають усі активні агенти, крім strategist та critic.

3. Логіка статусів прогону: дрібний прогін стартує одразу; великий стає в статус «чекає на схвалення плану» (власник дивиться план і тисне «Запустити»). Коли всі завдання відпрацьовані — статус «на твоїй перевірці».

4. Дашборд:
   - «Прогони рою» (/runs) — список прогонів та сторінка одного прогону (/runs/[id]) з планом, завданнями та прогрес-баром.
   - «На перевірці» (/review) — по кожному результату кнопки «Схвалити» та «На доопрацювання» (з коментарем).
   - Лічильник сповіщень у бічному меню (з таблиці events).

5. (Необов'язково) Telegram-сповіщення: src/notify.ts — бот пише власнику, коли план готовий до запуску або прогін завершено. Налаштування в .env (TELEGRAM_BOT_TOKEN, TELEGRAM_OWNER_CHAT_ID). Додай скрипт, який допомагає дізнатися свій chat_id (команда npm run telegram:chat-id).

6. Прогони npm run db:migrate, запусти проєкт, створи тестовий прогін із якоюсь ціллю та перевір увесь шлях: план → виконання → перевірка Критиком → зведення → «На перевірці» → схвалення. Наприкінці npm run typecheck.
